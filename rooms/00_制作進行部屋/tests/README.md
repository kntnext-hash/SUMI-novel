# セーブ・ロード回帰検証

`qa_save_restore.rpy` は製品のgameへ含めず、検証用に複製したgameへコピーする。
配布版の実行ファイルに検証用プロジェクト、`test qa_save_restore`、専用の`--savedir`を渡して実行する。
実行ごとに新しいsavedirを使い、テスト結果出力後もプロセスが残っていないか確認する。

初周と全彩再読それぞれの C01S01、C06S05、C12S06、EDS01 の本文表示後に保存する。
別モードのC01S02へ移り、保存ファイルをロードして、周回モード・本文位置・履歴末尾の本文・masterレイヤーの画像タグと属性が保存時と一致することを検証する。
保存と復元にはゲーム画面と同じFileSave/FileLoadアクションを使用する。上書き・ロードの確認ダイアログ操作は別途実画面で検査する。

地点への入口は検証専用の固定ラベルを使う。通読の証明ではなく、地点別の保存復帰の検証。
全ルートの本文到達と画像キュー照合は06室のqa_story_allで別途行う。
結果は実行先のsave_restore_results.jsonに8件記録され、全件passed=trueかつエンジンのStatus: PASSEDを合格条件とする。

ハーネス開発時に修正した点：冒頭Dissolveの完了前に保存しないようsay開始を待つ。メインメニューからのみStartを使う。ロード時の巻き戻しでテスト用の可変入口を再評価しないよう固定ラベル化。

再起動検証は、qa_save_restoreの合格を確認してそのプロセスを終了してから、同じsavedirで別プロセスを起動し、test qa_saved_restartを実行する。save_restore_results.jsonの8件を期待値として全件読み直し、save_restart_results.jsonの全件passedとエンジンのPASSEDを確認する。

qa_audio_cues.rpyは6か所のチャイム・通知キューを本文進行から発火し、soundチャンネルの再生中ファイルを期待値と照合する。音色・主観的な音量バランスはこの検査の対象外。

音響キュー検証は9件へ拡張：既存6件、第4章のメッセージ通知、第6章の着信開始、第6章の会話開始時の停止。最後の期待値Noneはsoundチャンネルの無音を意味する。2026-11-18に全9件PASSED。聴覚確認ではない。

qa_ambience.rpy：雨の複数周期ループ、通知との共存、翌朝での停止、冷蔵庫開始、教室での停止、保存ロード復帰、タイトル停止の7件を検証。初回はロード後復帰が失敗し、環境音の再設定を巻戻しガードより前へ移した後に全件PASSED。単発音の巻戻し抑制は維持。聴覚によるループ境界・音色評価は対象外。
